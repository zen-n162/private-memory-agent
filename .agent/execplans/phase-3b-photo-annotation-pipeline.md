# ExecPlan: Phase 3-B Photo Annotation Pipeline

## Goal

Add a local-first photo annotation pipeline that selects unannotated image media rows, calls a pluggable `VisionModelClient`, and stores caption/object/OCR metadata in `media_annotations`.

## Non-goals

- Do not require Qwen3-VL, Florence, PaddleOCR, or any real model in unit tests.
- Do not run face recognition.
- Do not implement full multimodal retrieval or agent orchestration.
- Do not modify, move, rename, copy, or delete source images.
- Do not log filenames, OCR text, GPS, names, note bodies, or LINE messages.

## Current State

The repository already has:

- Photo metadata ingestion into `source_items` and `media_items`.
- A flexible `media_annotations` table with `annotation_type`, `source`, `value_text`, `data_json`, `confidence`, `model_id`, `created_at`, and `updated_at`.
- Runtime abstractions including `VisionModelClient`, `VisionRequest`, `VisionInput`, `VisionResponse`, fake vision client, and a local OpenAI-compatible HTTP client.
- CLI support for `pma ingest photos` and `pma models ping`.

There is no command or service layer yet for generating photo annotations.

## Proposed Design

Create `private_memory_agent.annotation.photos` with:

- `PhotoAnnotation`: normalized model output.
- `PhotoAnnotationResult`: privacy-safe count-only summary.
- `annotate_photos`: opens SQLite, selects eligible media rows, batches requests, calls a `VisionModelClient`, and stores annotations.
- `select_unannotated_photo_media`: returns non-excluded image rows that do not already have a non-excluded `annotation_type='vision'` annotation.

CLI:

- Add `pma annotate photos`.
- Options: `--db`, `--limit`, `--batch-size`, `--client fake|openai-compatible`, `--model-key`, `--prompt`, `--config-dir`, `--config`, `--allow-remote`.
- Default client is the configured OpenAI-compatible local endpoint; fake mode must be selected explicitly for tests and smoke checks.

Real local model usage:

- `--client openai-compatible --model-key vision_common`
- Uses configured `endpoint_url` from `models.example.yaml` or local config.
- Sends source image bytes as base64 to the local endpoint only.

## Data Contracts

Stored `media_annotations` row:

- `media_item_id`: target media row.
- `annotation_type`: `vision`.
- `source`: `model`.
- `value_text`: caption text.
- `data_json`: JSON object with `objects`, `ocr_text`, `raw`, and `annotation_phase`.
- `confidence`: optional numeric confidence.
- `model_id`: model/client identifier.

`PhotoAnnotation` fields:

- `caption: str | None`
- `objects: tuple[str, ...]`
- `ocr_text: str | None`
- `confidence: float | None`
- `model_id: str`
- `raw: dict`

## Implementation Steps

1. Add annotation package and photo annotation dataclasses.
2. Add query for unannotated image `media_items`.
3. Add request construction that reads source images read-only and sends base64 image inputs to the selected vision client.
4. Add response normalization from `VisionResponse` including optional `objects`, `ocr_text`, and `confidence` from raw payloads.
5. Insert one resume-safe `media_annotations` row inside a transaction and skip rows already annotated by another run.
6. Add `pma annotate photos` CLI command and client factory.
7. Add tests with fake vision clients and synthetic fixture images.
8. Document Qwen3-VL, Florence, and PaddleOCR roles.
9. Run `pytest -q`.

## Tests and Verification

Run:

- `pytest -q`

Tests should cover:

- Selecting only unannotated image media rows.
- Storing caption, objects, OCR text, confidence, model name, and timestamps.
- Resume-safe behavior when run twice.
- `--limit` and `--batch-size`.
- CLI output does not include filenames or OCR text.

## Privacy and Security

The command prints count-only summaries. It does not log image filenames, OCR text, GPS, or model outputs. Source images are opened read-only only when an annotation client is invoked. Remote endpoint URLs are rejected by default by the existing HTTP client validation.

## Performance and Hardware

Default fake client tests are CPU-only and model-free. Real Qwen3-VL or Florence/PaddleOCR execution depends on user-started local model servers. Batch size controls per-run memory pressure; default is conservative.

## Rollback

Remove the annotation package, CLI command, tests, and docs additions. `media_annotations` rows generated by this phase are local derived data and can be excluded or deleted manually if needed.
